# Dayen security checklist

Этот файл фиксирует обязательные настройки перед демонстрацией, хостингом или передачей проекта.

## Аккаунты и роли

- `OWNER_EMAIL` должен указывать только на реальный аккаунт владельца.
- Владелец включает 2FA в `/settings` до работы с админкой.
- Только владелец может выдавать и забирать роль администратора.
- Админка недоступна без включенной 2FA.

## Переменные окружения

- `APP_BASE_URL` должен быть публичным адресом сайта.
- `CORS_ORIGINS` должен содержать только разрешенные адреса frontend.
- `COOKIE_SECURE=1` на production с HTTPS.
- `RUN_MIGRATIONS_ON_START=1` допустимо для простого деплоя; для строгого production миграции лучше запускать отдельной командой.

## Авторизация

- Сессия хранится в `httpOnly` cookie `dayen_session`.
- Старые localStorage-токены автоматически переносятся в cookie через `/api/auth/me`.
- Новые сессии в базе хранятся в SHA-256 виде, старые токены поддерживаются только для мягкого перехода.
- Вход, регистрация, восстановление пароля и 2FA ограничены rate limit.

## Загрузка файлов

- Разрешены только изображения: PNG, JPEG, WEBP, GIF, ICO.
- Проверяется не только MIME-тип, но и сигнатура файла.
- Файл с неверной сигнатурой удаляется после загрузки.
- Support uploads доступны только администраторам.

## Аудит

- Действия администраторов пишутся в журнал.
- В журнал добавляются IP и User-Agent.
- Журнал должен проверяться владельцем после изменения ролей, банов, товаров, разделов, баннера, заказов и обращений.

## Перед сдачей или продажей

- Выполнить `npm run api:migrate`.
- Выполнить `npm run api:build`.
- Выполнить `npm run web:build`.
- Выполнить `npm run api:test`.
- Проверить `/settings`: у владельца включена 2FA.
- Проверить `/admin`: без 2FA должен быть редирект в настройки.
